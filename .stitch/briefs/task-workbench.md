# Architect Workbench

## Core job

Let a senior engineer see the governed task frontier, understand dependency and safety blockers, inspect the complete context obligation for one selected task, and copy that context into another tool.

## Authoritative inputs

- The existing task planner determines readiness and blockers.
- Task front matter supplies dependency, decision, reading and write-scope facts.
- Git supplies branch, revision and dirty state.
- The context compiler supplies the exact governing and historical reading pack.

## First workflow

1. Open the workbench and see ready, active, blocked and done tasks.
2. Select a task from the rail or dependency graph.
3. Inspect direct dependencies, blockers, decisions, required reading and write scope.
4. Resolve a mechanical blocker through a preview-bound named operation.
5. Inspect the execution receipt and automatically refreshed task plan.
6. Refresh, copy or inspect the complete governed task context.

## Scope

One desktop feature surface hosted temporarily by a disposable preview shell. It will fold into the larger AIFSD desktop application and is not a standalone product boundary. The surface may execute only named, preview-bound remediation operations with explicit confirmation, receipts and automatic replanning. It exposes no arbitrary shell, chat, agents, settings, analytics or project creation.

## Interaction authority

- Resizable task, graph and context panes persist their proportions and retain accessible keyboard controls.
- Workspace checkpoint and path-scoped stash operations bind execution to an exact HEAD and status digest.
- Removing the running workbench source is rejected while this disposable host serves it.
- A remediation receipt records the operation identity, before and after state, affected paths, validation and planner rerun.
- Task lifecycle changes remain governed coordinator operations and may not bypass required reading, evidence or completion admission.
